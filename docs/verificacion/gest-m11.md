## Límites de seguridad comprobables

- `ProductionOperationsController::productionScope()` usa `authorizedBranchScope` y exige permiso por operación (`inventory.view`, `inventory.create`, `inventory.update`) **antes** de resolver la fuente y entitlement `production-lite` del tenant. Los filtros de consulta de órdenes usan `{tenant, source}`; la finalización busca `{id, tenant, source}`.
- Negativos HTTP existentes: `ProductionOperationsControllerTest::testPermissionsCsrfCrossTenantStaleBomOrForeignOrderFailClosed` comprueba 403 (rol sin `inventory.create` o CSRF ausente) y 404 (orden de otro tenant); `testBomSnapshotAndVersionCreationAreTenantScopedAndEntitled` contrasta BOM de dos tenants.
- UI actual `frontend/admin/ProductionManagement.tsx`: renderiza loading, vacío de órdenes, error y módulo deshabilitado. **No** renderiza un estado explícito `permission-denied` para usuarios sin `inventory.view` (devuelve `null`): esto y los estados de la UI integral siguen pendientes en las hijas. No atribuir cobertura completa a partir de este panel.
- **No se modificaron** `docs/matriz-cobertura.md`, `datos.yml`, entitlements comerciales ni despliegues. El seguimiento de todas las brechas permanece abierto en #1575 y #1576; cualquier promoción de cobertura requiere un PR posterior con pruebas exactas.
